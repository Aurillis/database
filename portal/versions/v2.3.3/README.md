# Portal v2.3.3 — 侧边栏分类 UX 修复

**日期**：2026-09-22
**类型**：主站 Portal PATCH（纯前端，无 SCF 改动）

## 改了什么

只改根 `index.html` 侧边栏渲染（`renderSidebar` 内分类树段），共 2 处：

1. **空子分类不再隐藏**（约 1131 行）
   - 旧：`if (count === 0) return;` → 子分类 0 文件直接不渲染。
   - 新：`if (count === 0 && child.id === 'other') return;` → 只有内置 `other` 为空时隐藏，其余空子分类正常显示（计数 0）。
   - 根因场景：用户在父分类「新品调研」下新建「FDA代码库」，因空分类被隐藏而"凭空消失"。

2. **「未归类」→「直属文件」**（约 1126 行）
   - 该标签的真实含义是"直接挂在该父分类下、未归入任何子分类的文件"，旧文案易被误解为"分类变成了未归类"。

## 触发场景（为什么修）

用户新建「FDA代码库」（父级=新品调研）→ 空子分类被隐藏看不见 → 同时新品调研展开后显示「未归类」（其直属文件）→ 用户误以为新建的分类变成了"未归类"。

## 部署方式

- 推 `main` 后 GitHub Pages 自动生效（约 1–2 分钟）；**无需重传 SCF**。
- `index.js`（SCF 快照）仅作版本留档，与 v2.3.2 相同、无改动。

## 回滚

把 `portal/versions/v2.3.2/index.html` 复制回根目录 → 推 GitHub Pages。
